# Apollo's Reader

A reading environment for Plato's *Apology* in Greek, built for coursework.

Three ways to read, and every Greek word is clickable:

| Mode | What it gives you |
| --- | --- |
| **Parallel** | Greek beside Fowler's translation, aligned section by section |
| **Interlinear** | Greek across the page with a gloss under each word |
| **Greek** | The text on its own |

Click any word for its parse, its dictionary headword, and the full
Liddell-Scott-Jones entry. Nothing is fetched from a dictionary server while you
read — the parses and the entries are built into the site.

It is a static site: HTML, one stylesheet, one script, and JSON. No build step,
no framework, no dependencies.

## Using it

- **1 / 2 / 3** switch modes, **/** searches, **,** opens display settings,
  **s** opens the section list, **n / p** move a section, **Esc** closes things.
- Search ignores accents and breathings, so `ανθρωπος` finds ἄνθρωπος. Typing
  Latin letters searches the translation instead.
- Display settings cover theme, accent colour, Greek typeface, type size, line
  spacing, column width, which side the translation sits on, and whether to show
  Stephanus markers or a per-section vocabulary list. They are remembered.
- Any section can be linked directly: `.../#28a`.

## How the data is made

Everything under `data/` is generated by the scripts in `tools/`. Run them in
order; each is re-runnable and caches its downloads under `cache/`, which is not
committed.

```bash
python tools/build_text.py                    # TEI -> aligned reading chunks
python tools/build_morph.py plato-apology     # every word form -> headword + parse
python tools/build_lexicon.py plato-apology   # the LSJ entries this text needs
python tools/stamp_assets.py                  # after editing anything in assets/
```

`stamp_assets.py` rewrites the `?v=` on the stylesheet and script in
`index.html` to a hash of their contents. GitHub Pages serves both under the
same name forever, so without it a returning reader can run yesterday's script
against today's data until their cache expires.

**`build_text.py`** downloads the Greek and English TEI from the Perseus
canonical repository and flattens both into chunks. The two editions carry an
identical sequence of `<milestone unit="section" resp="Stephanus"/>` markers, so
those markers are the alignment key: chunk `24b` of the Greek is the same
passage as chunk `24b` of the translation. For the *Apology* that yields 125
aligned sections from 17a to 42a.

**`build_morph.py`** collects the distinct word forms (2,614 lookup keys over
8,750 tokens) and resolves each against the Perseids Morpheus service, caching
every response. Elision is handled from a hand-written table in the script
rather than by guessing: Morpheus cannot parse `ἀλλ'`, and probing for the
missing vowel produces confident nonsense (`παρ'` resolves to a form of πηρός).
Current coverage is 99.95% of tokens; what is left is two proper names Morpheus
does not carry and two single-letter fragments from the editorial brackets.

**`build_lexicon.py`** scans the Perseus LSJ — 283 MB of TEI across 27 files —
and keeps only the headwords this text needs, converting each from betacode to
Unicode. Entries are written one file per headword so that tapping a word on a
phone costs a few kilobytes rather than a few megabytes.

Two things in the source data are worth knowing about if you extend this:

- Perseus dictionary keys carry **vowel-quantity marks** (`do/ca^` is δόξα with
  a breve). They are editorial metadata, not letters, and silently break every
  headword that has one if you leave them in.
- LSJ tags Indo-European cognates with the same `<tr>` element it uses for real
  translations, so scraping glosses naively offers *"nar-, ner-, nṛ-"* as the
  meaning of ἀνήρ. The scraped gloss is therefore filtered, and the commonest
  few hundred words are glossed by hand in `tools/supplement.json`.

### `tools/supplement.json`

Editorial material written for this reader, not taken from LSJ: short glosses
for the high-frequency words, a sentence of orientation for each person and
place named in the dialogue, and a list of headwords Morpheus offers that are
wrong here (`δοκῶ` is δοκέω "seem", not δοκός "beam"). The reader always shows
the unaltered LSJ entry underneath.

### Adding another text

Add an entry to `WORKS` in `tools/build_text.py` with its CTS URN and the file
names of its Greek and English TEI, then run the three scripts with the new
slug. `build_lexicon.py` takes several slugs at once and will pull the union of
the headwords they need. The front end reads `data/index.json`; point `WORK` at
the top of `assets/app.js` at the new slug, or extend it into a picker.

## Running it locally

Any static server will do — the browser blocks `fetch` on `file://` URLs.

```bash
python -m http.server 8765
```
